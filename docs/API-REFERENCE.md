# RHEX Trade-In API Reference

**Base URL:** `https://rhex.app/api/v1`

## Authentication

All endpoints require an API key passed via the `X-API-Key` header.

```
X-API-Key: rhx_your_api_key_here
```

API keys are generated by the RHEX admin team and provided to you during onboarding. Keep your key secure — it cannot be retrieved after initial generation.

## Sandbox / Testing

Sandbox API keys let you test the full API lifecycle without affecting real trade-ins or triggering any side effects.

**How sandbox keys work:**

- Sandbox keys use the prefix `rhx_test_` (production keys use `rhx_`)
- Quotes created with a sandbox key include `"sandbox": true` in the response
- Sandbox and production are fully separated: a sandbox key can only read or act on sandbox quotes, and a production key can only read or act on production quotes. Requests for a quote from the other environment return `404`
- Sandbox quotes are flagged and excluded from your partner portal, dashboard stats and earnings
- Sandbox quotes expire after **1 hour** (production quotes expire after 14 days)
- No emails are sent (acceptance confirmation, revision notifications, payment confirmation)
- No customer records are created or updated
- No commission entries are generated

**Example sandbox response:**

```json
{
  "id": "quote_xyz789",
  "deviceId": "abc123",
  "grade": "B",
  "quotePrice": 580,
  "status": "quoted",
  "sandbox": true,
  "expiresAt": "2026-08-12T03:30:00.000Z"
}
```

Sandbox quotes use real device data and pricing — the differences are that no side effects occur, quotes expire quickly, and they're kept separate from your production quotes. Request a sandbox key from the RHEX admin team to get started.

## Rate Limiting

All endpoints are rate-limited to **300 requests per minute** per API key. When exceeded, the API returns `429 Too Many Requests` with a `Retry-After` header indicating how many seconds to wait.

## Currency

Prices are returned in your configured currency (NZD or AUD). Each response includes a `displayCurrency` field indicating which currency prices are in.

- `*NZD` fields (e.g. `partnerPriceNZD`) are always in New Zealand dollars
- Non-suffixed price fields (e.g. `partnerPrice`) are in your display currency

## Error Responses

All errors return JSON with an `error` field:

```json
{ "error": "Description of the error" }
```

| Status | Meaning |
|--------|---------|
| 400 | Bad request — missing or invalid parameters |
| 401 | Unauthorized — invalid or revoked API key |
| 404 | Not found — resource doesn't exist, belongs to the other environment (sandbox vs production), or has no pricing available |
| 429 | Rate limit exceeded — wait and retry |
| 500 | Internal server error |

### 1. Search Devices

Search and list available devices with your partner pricing.

```
GET /api/v1/devices
```

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `q` | string | — | Search text (min 2 chars). Matches against make + model |
| `make` | string | — | Filter by manufacturer (e.g. `Apple`, `Samsung`) |
| `category` | string | — | Filter by category (e.g. `Phone`, `Tablet`, `Watch`) |
| `limit` | integer | 50 | Results per page (max 200) |
| `offset` | integer | 0 | Pagination offset |

**Example Request:**

```bash
curl -H "X-API-Key: rhx_your_key" \
  "https://rhex.app/api/v1/devices?q=iphone+15&limit=10"
```

**Example Response:**

```json
{
  "devices": [
    {
      "id": "abc123",
      "make": "Apple",
      "model": "iPhone 15 Pro",
      "storage": "256GB",
      "category": "Phone",
      "grades": {
        "A": { "partnerPriceNZD": 810, "partnerPrice": 745 },
        "B": { "partnerPriceNZD": 630, "partnerPrice": 580 },
        "C": { "partnerPriceNZD": 450, "partnerPrice": 415 },
        "D": null
      }
    }
  ],
  "grades": [
    { "key": "A", "label": "Grade A" },
    { "key": "B", "label": "Grade B" },
    { "key": "C", "label": "Grade C" },
    { "key": "D", "label": "Grade D" }
  ],
  "total": 1,
  "limit": 10,
  "offset": 0,
  "displayCurrency": "AUD"
```

**Notes:**
- Only active devices are returned
- A `null` grade means no pricing is available for that condition
- Use the `id` field when creating quotes

### 3. Create Quote

Create a single-device trade-in quote. Quotes are valid for 14 days.

```
POST /api/v1/quotes
```

**Request Body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `deviceId` | string | Yes | Device ID (from search/pricing endpoints) |
| `grade` | string | Yes | Condition grade (e.g. `A`, `B`, `C`) |
| `imei` | string | No | 15-digit IMEI number |

**Example Request:**

```bash
curl -X POST \
  -H "X-API-Key: rhx_your_key" \
  -H "Content-Type: application/json" \
  -d '{"deviceId": "abc123", "grade": "B"}' \
  "https://rhex.app/api/v1/quotes"
```

**Example Response (201 Created):**

```json
{
  "id": "quote_xyz789",
  "deviceId": "abc123",
  "grade": "B",
  "quotePriceNZD": 630,
  "publicPriceNZD": 700,
  "quotePrice": 580,
  "publicPrice": 645,
  "displayCurrency": "AUD",
  "status": "quoted",
  "source": "api",
  "createdAt": "2026-08-12T02:30:00.000Z",
  "expiresAt": "2026-08-26T02:30:00.000Z"
}
```

**Notes:**
- `quotePrice` is the amount you'll pay the customer (in display currency)
- `quotePriceNZD` is always in NZD for reconciliation
- The quote expires after 14 days

### 4. Get Quote

Retrieve a quote by ID. Use this to check quote status.

```
GET /api/v1/quotes/{id}
```

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | string | Quote ID (from create response) |

**Example Request:**

```bash
curl -H "X-API-Key: rhx_your_key" \
  "https://rhex.app/api/v1/quotes/quote_xyz789"
```

**Example Response:**

```json
{
  "id": "quote_xyz789",
  "deviceId": "abc123",
  "grade": "B",
  "quotePriceNZD": 630,
  "publicPriceNZD": 700,
  "quotePrice": 580,
  "displayCurrency": "AUD",
  "status": "quoted",
  "source": "api",
  "imei": null,
  "customerName": null,
  "customerEmail": null,
  "createdAt": "2026-08-12T02:30:00.000Z",
  "expiresAt": "2026-08-26T02:30:00.000Z",
  "acceptedAt": null,
  "device": {
    "id": "abc123",
    "make": "Apple",
    "model": "iPhone 15 Pro",
    "storage": "256GB"
  }
}
```

**Quote Statuses:**

| Status | Meaning |
|--------|---------|
| `quoted` | Active quote, waiting for acceptance |
| `accepted` | Customer accepted, device expected |
| `shipped` | Device shipped to RHEX (optional: a quote can go straight from `accepted` to `received`) |
| `received` | Device received by RHEX |
| `on_hold` | Under review (e.g. ownership or blacklist checks). Payment is paused. The quote returns to its previous status when the review ends, or moves to `returning` |
| `revised` | Device inspected, quote revised — awaiting response |
| `inspected` | Inspection complete (or revision accepted), awaiting payment |
| `paid` | Trade-in completed, payment processed |
| `returning` | Revision rejected or expired, device being returned |
| `returned` | Device returned to customer, trade-in closed |
| `expired` | Quote not accepted before `expiresAt`, or accepted but the device was never sent. RHEX may still receive a device for an accepted quote that has expired, which moves it to `received` |
| `cancelled` | Quote cancelled |

> **New status values may be added.** Treat an unknown `status` as "in progress" rather than failing, and don't rely on the order of this table.

**Cancellation:** a quote can only be cancelled before RHEX has the device (`quoted`, `accepted` or `shipped`). Once the device has been received, the trade-in ends as `paid` or `returned`; a `paid` quote can't be cancelled.

**Revisions only go down:** RHEX revises a quote only when the device is worth less than quoted. If it's in better condition than declared, the original quote is paid.

**Revision Fields (present when status is `revised` or later):**

| Field | Type | Description |
|-------|------|-------------|
| `inspectionGrade` | string \| null | Grade assigned during inspection |
| `revisedPriceNZD` | number \| null | Revised price in NZD |
| `revisedDeviceId` | string \| null | Different device ID (if model/storage mismatch) |
| `revisedDeviceMake` | string \| null | Revised device make |
| `revisedDeviceModel` | string \| null | Revised device model |
| `revisedDeviceStorage` | string \| null | Revised device storage |
| `revisedAt` | string \| null | ISO timestamp when revision was created |
| `revisionExpiresAt` | string \| null | ISO timestamp — deadline to respond |
| `returningAt` | string \| null | ISO timestamp when return was initiated |
| `returnedAt` | string \| null | ISO timestamp when device was returned |

When a quote is in `revised` status, the partner must respond before `revisionExpiresAt` (**7 days** after the revision). If no response is received, the quote auto-transitions to `returning` and the device is sent back.

### 5. Accept Quote

Accept a quote by providing customer details and payment information. This triggers a confirmation email to the customer.

```
PUT /api/v1/quotes/{id}/accept
```

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | string | Quote ID |

**Request Body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `customerName` | string | Yes | Customer's full name |
| `customerEmail` | string | Yes | Customer's email address |
| `customerPhone` | string | Yes | Customer's phone number |
| `shippingAddress` | string | Yes | Address for shipping the device |
| `paymentMethod` | string | No* | `"payid"` or `"bank_transfer"` |
| `payIdPhone` | string | If PayID | Phone number for PayID payment |
| `bankBSB` | string | If bank | BSB number |
| `bankAccountNumber` | string | If bank | Account number |
| `bankAccountName` | string | If bank | Account holder name |
| `imei` | string | No | 15-digit IMEI (if not provided at quote creation) |

> \* **Payment method fields are optional for Mode B partners.** In Mode B, RHEX pays the partner via their registered payment method — customer payment details are not required. If provided, they will be stored for record-keeping.

**Example Request (PayID):**

```bash
curl -X PUT \
  -H "X-API-Key: rhx_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "customerName": "John Smith",
    "customerEmail": "john@example.com",
    "customerPhone": "0412345678",
    "shippingAddress": "123 Main St, Sydney NSW 2000",
    "paymentMethod": "payid",
    "payIdPhone": "0412345678"
  }' \
  "https://rhex.app/api/v1/quotes/quote_xyz789/accept"
```

**Example Request (Bank Transfer):**

```bash
curl -X PUT \
  -H "X-API-Key: rhx_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "customerName": "John Smith",
    "customerEmail": "john@example.com",
    "customerPhone": "0412345678",
    "shippingAddress": "123 Main St, Sydney NSW 2000",
    "paymentMethod": "bank_transfer",
    "bankBSB": "062000",
    "bankAccountNumber": "12345678",
    "bankAccountName": "John Smith"
  }' \
  "https://rhex.app/api/v1/quotes/quote_xyz789/accept"
```

**Example Response:**

```json
{
  "id": "quote_xyz789",
  "deviceId": "abc123",
  "grade": "B",
  "quotePriceNZD": 630,
  "publicPriceNZD": 700,
  "quotePrice": 580,
  "displayCurrency": "AUD",
  "status": "accepted",
  "source": "api",
  "customerName": "John Smith",
  "customerEmail": "john@example.com",
  "createdAt": "2026-08-12T02:30:00.000Z",
  "expiresAt": "2026-08-26T02:30:00.000Z",
  "acceptedAt": "2026-08-13T10:15:00.000Z",
  "device": {
    "id": "abc123",
    "make": "Apple",
    "model": "iPhone 15 Pro",
    "storage": "256GB"
  }
}
```

**Validation Rules:**
- Quote must be in `"quoted"` status (not already accepted or expired)
- Quote must not be past its `expiresAt` date
- PayID requires `payIdPhone`
- Bank transfer requires `bankBSB`, `bankAccountNumber`, and `bankAccountName`

### 6. Respond to Revised Quote

When a device is inspected and the condition, model, or storage differs from the original quote, RHEX will revise the quote. The quote status changes to `revised` and you must accept or reject the new offer before the `revisionExpiresAt` deadline.

```
PUT /api/v1/quotes/{id}/respond
```

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | string | Quote ID |

**Request Body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `action` | string | Yes | `"accept"` or `"reject"` |

**Example Request (Accept):**

```bash
curl -X PUT \
  -H "X-API-Key: rhx_your_key" \
  -H "Content-Type: application/json" \
  -d '{"action": "accept"}' \
  "https://rhex.app/api/v1/quotes/quote_xyz789/respond"
```

**Example Response:**

```json
{
  "id": "quote_xyz789",
  "status": "inspected"
}
```

**Example Request (Reject):**

```bash
curl -X PUT \
  -H "X-API-Key: rhx_your_key" \
  -H "Content-Type: application/json" \
  -d '{"action": "reject"}' \
  "https://rhex.app/api/v1/quotes/quote_xyz789/respond"
```

**Example Response:**

```json
{
  "id": "quote_xyz789",
  "status": "returning"
}
```

**Behaviour:**
- `accept` — Accepts the revised price. Status moves to `inspected`, then RHEX processes payment.
- `reject` — Rejects the revised price. Status moves to `returning` and the device is shipped back.
- If no response is received before `revisionExpiresAt`, the quote auto-transitions to `returning`.

**Validation Rules:**
- Quote must be in `revised` status
- Must not be past the `revisionExpiresAt` deadline

### 7. Create Bulk Quote

Create a bulk quote from either a CSV manifest or a device list. Useful for quoting multiple devices at once.

```
POST /api/v1/bulk-quotes
```

**Option A — CSV Manifest:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `csv` | string | Yes | CSV content with header row |
| `assumedGrade` | string | No | Default grade for all rows (default: middle grade) |
| `category` | string | No | Device category (default: `"Phone"`) |

The CSV should have a header row. Recognised column names:

| Column | Synonyms |
|--------|----------|
| Device | `device`, `model`, `phone`, `handset`, `product`, `description`, `item`, `name` |
| Quantity | `quantity`, `qty`, `count`, `units`, `amount` |
| Storage | `storage`, `capacity`, `memory`, `size`, `gb` |
| Make | `make`, `brand`, `manufacturer`, `oem` |
| Grade | `grade`, `condition`, `quality`, `tier` |

**Example Request (CSV):**

```bash
curl -X POST \
  -H "X-API-Key: rhx_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "csv": "device,quantity\niPhone 15 Pro 256GB,5\nSamsung Galaxy S24,3",
    "assumedGrade": "B",
    "category": "Phone"
  }' \
  "https://rhex.app/api/v1/bulk-quotes"
```

**Option B — Device List:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `devices` | array | Yes | Array of device objects |
| `devices[].deviceId` | string | Yes | Device ID (from search endpoint) |
| `devices[].quantity` | integer | No | Number of units (default: 1) |
| `devices[].grade` | string | No | Condition grade (uses `assumedGrade` if omitted) |
| `category` | string | No | Device category (default: `"Phone"`) |
| `assumedGrade` | string | No | Default grade (default: middle grade) |

**Example Request (Device List):**

```bash
curl -X POST \
  -H "X-API-Key: rhx_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "devices": [
      { "deviceId": "abc123", "quantity": 5, "grade": "B" },
      { "deviceId": "def456", "quantity": 3, "grade": "C" }
    ],
    "category": "Phone"
  }' \
  "https://rhex.app/api/v1/bulk-quotes"
```

**Example Response (201 Created):**

```json
{
  "id": "bulk_abc123",
  "totalDevices": 8,
  "totalIndicativeNZD": 4200,
  "totalIndicative": 3865,
  "displayCurrency": "AUD",
  "matchedCount": 2,
  "unmatchedCount": 0,
  "lineCount": 2
}
```

**Notes:**
- CSV mode uses fuzzy matching to identify devices from free-text descriptions
- Device list mode uses exact device IDs (recommended for accuracy). IDs that aren't active devices in the requested `category` are counted as unmatched and priced at 0
- An invalid per-device or per-row `grade` falls back to `assumedGrade`
- `matchedCount` / `unmatchedCount` indicates how many rows were matched to known devices
- `totalIndicative` is the estimated total payout in your display currency
- Limits: up to 2,000 rows or devices per request, and a quantity of up to 10,000 per line. Larger requests return `400`

## Typical Integration Flow

1. **Search for devices** — `GET /api/v1/devices?q=iphone` to build your device catalogue / search UI
2. **Show pricing** — `GET /api/v1/devices/{id}/price` to display grade-by-grade pricing to the customer
3. **Create quote** — `POST /api/v1/quotes` when the customer selects a device and grade
4. **Collect customer info** — your frontend collects name, email, phone, address, payment details
5. **Accept quote** — `PUT /api/v1/quotes/{id}/accept` to lock in the trade-in
6. **Track status** — `GET /api/v1/quotes/{id}` to poll for status updates
7. **Handle revisions** — If the quote moves to `revised` status, call `PUT /api/v1/quotes/{id}/respond` with `accept` or `reject`

For bulk operations (e.g. processing a manifest of devices from an IT refresh):

1. **Create bulk quote** — `POST /api/v1/bulk-quotes` with CSV or device list
2. **Review results** — `GET /api/v1/bulk-quotes/{id}` to see matched devices and pricing
3. **Accept** — `PUT /api/v1/bulk-quotes/{id}/accept` to go ahead with the trade-in
4. **Track status** — `GET /api/v1/bulk-quotes/{id}` to poll for status updates
5. **Handle revisions** — If revised after inspection, call `PUT /api/v1/bulk-quotes/{id}/respond`
